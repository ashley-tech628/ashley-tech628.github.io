01 / PROBLEM

What needed to work.

A plausible chart answer can still be wrong. Image perception, arithmetic, label lookup and answer formatting introduce different failure modes.

02 / APPROACH

The engineering behind it.

Structure chart evidence, route questions to specialist solvers, collect candidate answers on a shared blackboard, then apply critique and normalization before the final decision.

  1. 01

    Typed ChartDSL keeps values connected to chart groups and categories.

  2. 02

    Solver branches isolate lookup, comparison, counting and arithmetic.

  3. 03

    Prediction audits check paired IDs, labels, missing outputs and report consistency.

  4. 04

    The no-key offline demo uses a known structured fixture and records an inspectable trace.

TECHNICAL DEEP DIVE

From implementation to evidence.

Routing, critique and verification

Typed chart evidence binds values to categories and groups; specialized solvers address lookup, comparison, counting and arithmetic. Candidate answers and critiques support a final verification step instead of hiding all reasoning behind a single response. Auditing pairs prediction IDs with reference labels, checks missing outputs and verifies reported scores.
