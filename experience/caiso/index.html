01 / ARCHITECTURE

A connected workflow, with explicit domain boundaries.

Task management defines the training requirements. Course management connects tasks to instructional objectives. Class scheduling records delivery, activities and learner outcomes. Evaluation connects demonstrated competence back to the qualification record. The engineering challenge is preserving that relationship across changes rather than treating each screen as an independent CRUD page.

The deployed stack uses PHP on IIS/FastCGI with the SQL Server driver and a shared relational database. Table families separate domain ownership, while association tables link task versions to courses, objectives and qualification cards. The help engine is a separate cross-cutting subsystem rather than a source of qualification evidence.

02 / VERSION-AWARE DATA

Separate business identity from the exact revision.

A stable task number identifies a requirement across time; a separate version-specific row identifies its exact revision. This distinction allows historical qualification evidence to refer to what was actually evaluated, rather than silently inheriting today's task text.

Insert-only checkoffs and frozen qualification cards are required design invariants; the migration suite records enforcement gaps, so this case does not claim complete immutability in every legacy write path.

03 / COURSE ENGINEERING

Make training design traceable to the task list.

The documented course workflow spans 12 tabs, from draft creation and task linking through analysis, objectives, delivery planning, quiz design, implementation, evaluation and a read-only summary. Course-level and objective-level task associations serve different questions and must both be preserved.

Course ownership limits instructor edits to their own records, with administrative oversight for ownership changes. Normalized associations connect a course and its objectives to exact task versions. Legacy string-based associations are a migration concern, not the model for new writes.

Cross-module verification

Validation follows the seams: task-version references must agree in course objectives; scheduled class metadata must match the linked course; roster outcomes must agree across the screen, PDF and CSV exports; completion identity, date and task version must agree across evaluation views and qualification reports.

04 / DETERMINISTIC RETRIEVAL

Ground help in an approved, versioned corpus.

The help subsystem uses field-weighted BM25F and Reciprocal Rank Fusion across four retrieval lanes. A confidence gate controls whether a ranked result is suitable to present. Query and candidate logs make retrieval behavior inspectable. It operates over roughly 123 approved article versions in the documentation, presented as 120+ in the résumé.

This is a deterministic search system: the documented implementation has no LLM dependency and makes no outbound inference calls. It remains separate from the qualification data flow. Its value is controlled knowledge retrieval and inspectable ranking, not generated compliance decisions.

05 / PRODUCTION ENGINEERING

Validate the whole workflow under real runtime constraints.

Worked with training, engineering and IT teams on workflow validation, database checks, load testing, session optimization, IIS/FastCGI tuning and deployment checks. The shared runtime makes cross-module load and per-user session behavior relevant engineering concerns; checking one module in isolation does not establish end-to-end capacity.

  1. 01

    Business correctness: verify associations, version references, evaluator identity and consistency of generated reports.

  2. 02

    Runtime behavior: examine shared worker capacity, concurrent request handling and session lifecycle management.

  3. 03

    Release quality: validate database behavior, deployed configuration and repeatable environment checks with stakeholder review.

The suite documents an implemented scheduled session-cleanup control. It does not provide a publishable before/after performance dataset, so no throughput, latency reduction or availability figure is asserted here.
